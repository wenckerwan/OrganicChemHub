# OrganicChemHub 后续更新规划

版本：v1.0  
日期：2026-07-28  
基准版本：OrganicChemHub 0.1

---

## 1. 当前版本状态

OrganicChemHub 0.1 已完成基础资料库能力：

- Django 项目骨架。
- 人名反应、反应类型、标签、官能团模型。
- 合成路线、路线步骤模型。
- Django Admin 后台维护。
- 首页、反应列表、反应详情、路线列表、路线详情。
- 基础关键词搜索与筛选。
- 已发布内容公开展示，草稿内容隐藏。
- 示例数据和基础测试。

后续更新应优先提升“资料录入效率、搜索准确性、学习体验和部署稳定性”，再进入复杂的结构检索和智能合成分析。

---

## 2. 更新原则

### 2.1 优先级原则

1. 先把内容库做扎实，再做智能功能。
2. 先优化管理员录入体验，再扩展普通用户功能。
3. 先实现确定性检索，再引入结构式检索和智能推荐。
4. 先保证数据质量和可维护性，再追求视觉复杂度。

### 2.2 版本节奏

建议采用小版本快速迭代：

| 版本 | 主题 | 核心目标 |
| --- | --- | --- |
| 0.2 | 内容维护增强 | 提升后台录入效率和内容规范性 |
| 0.3 | 搜索与分类增强 | 让学生更快找到目标反应和路线 |
| 0.35 | UI 与前端结构式展示 | 提升网站观感，并用前端库渲染 SMILES |
| 0.36 | 查询页与考研反应扩充 | 借鉴目录式查询体验，并扩充考研常见反应 |
| 0.37 | 图片结构式与后台维护 | 改为图片优先展示，并支持后台上传替换 |
| 0.4 | RDKit 结构能力 | 将结构式校验、缓存和子结构基础能力移到后端 |
| 0.5 | 学习专题 | 从查询工具扩展为复习辅助工具 |
| 0.6 | 数据导入导出 | 支持批量录入和批量维护 |
| 0.7 | 用户收藏笔记 | 支持个人学习资料夹 |
| 0.8 | 生产部署 | 完善上线、备份和安全配置 |
| 0.9 | 结构式检索实验版 | 探索 RDKit 子结构检索 |
| 1.0 | 稳定公开版 | 形成可公开使用的网站 |

## 3. 0.2 内容维护增强

### 3.1 目标

让管理员更高效、更规范地录入人名反应和合成路线，减少数据不完整和格式混乱。

### 3.2 功能范围

- Admin 表单分组继续优化。
- 反应和路线增加“内容完整度”提示。
- 增加批量发布、批量下架操作。
- 增加更新时间、创建时间筛选。
- 增加列表页中路线步骤数量显示。
- 增加基础内容校验：
  - 已发布反应必须有中文名、英文名、摘要、条件、参考来源。
  - 已发布路线必须有目标产物、摘要、至少一个步骤。

### 3.3 验收标准

- 管理员能在后台批量发布或下架反应和路线。
- 不完整内容不能直接设为已发布，或至少给出明确错误提示。
- 路线后台列表能看到每条路线的步骤数量。
- 测试覆盖发布校验和批量操作。

### 3.4 建议修改范围

- `reactions/admin.py`
- `reactions/models.py`
- `reactions/tests.py`
- 可选新增 `reactions/validators.py`

## 4. 0.3 搜索与分类增强

### 4.1 目标

提升学生查找资料的效率，支持更接近复习场景的检索方式。

### 4.2 功能范围

## 5. 0.4 结构式展示

### 5.0 0.35 已完成的过渡能力

0.35 先解决“页面好看”和“能看见结构式”的问题，不强制服务器安装 RDKit：

- 前台导航、首页、反应卡片、详情页视觉升级。
- 反应详情页将 `equation_smiles` 渲染为反应物、箭头和产物结构式区域。
- 路线详情页展示目标产物结构式，并在步骤中展示反应物/产物结构式。
- 页面保留原始 SMILES，便于复制和排错。
- Django Admin 增加 OrganicChemHub 标题和基础主题样式。

### 5.1 目标

让反应和路线详情页从前端结构式展示升级为更稳定的后端结构能力。

### 5.2 功能范围

- 引入 RDKit，用于 SMILES 校验。
- 将分子 SMILES 在后端渲染为 SVG 并缓存。
- 在反应详情页展示反应物和产物结构。
- 在路线详情页展示每一步结构变化。
- 对非法 SMILES 给出后台校验提示。
- 对结构 SVG 做缓存，避免每次请求重复渲染。

### 5.3 技术建议

- 优先使用服务层封装 RDKit 调用。
- 不在视图里直接写 RDKit 逻辑。
- 结构渲染失败时页面仍可正常展示文本信息。
- Windows 本地开发可使用 Conda 或 Docker 解决 RDKit 安装问题。

### 5.4 验收标准

- 合法 SMILES 能在详情页显示结构图。
- 非法 SMILES 在后台保存时提示错误。
- 没有 SMILES 的内容不会导致页面报错。
- 测试覆盖合法、非法、空值三类输入。

### 5.5 建议修改范围

- `requirements.txt`
- `reactions/services/chemistry.py`
- `reactions/models.py`
- `reactions/views.py`
- `templates/reactions/reaction_detail.html`
- `templates/reactions/route_detail.html`
- `reactions/tests.py`

## 7. 0.6 数据导入导出

### 7.1 目标

支持批量录入数据，降低维护 50 到 300 个反应时的人工成本。

### 7.2 功能范围

- 支持 CSV 或 Excel 导入反应数据。
- 支持 CSV 或 Excel 导入路线数据。
- 支持导出当前反应列表。
- 导入时进行字段校验。
- 导入失败时返回错误行号和错误原因。
- 增加数据录入模板文件。

### 7.3 技术建议

- 可使用 `django-import-export`。
- 第一阶段只导入反应基础字段。
- 路线步骤导入可以作为第二阶段功能。

### 7.4 验收标准

- 管理员能通过后台导入一批反应。
- 导入错误不会产生半成品脏数据。
- 导出文件能被 Excel 正常打开。
- README 中提供导入模板说明。

## 8. 0.7 用户系统与收藏笔记

### 8.1 目标

支持学习者建立个人复习资料夹。

### 8.2 功能范围

- 用户注册、登录、退出。
- 收藏人名反应。
- 收藏合成路线。
- 用户笔记。
- 个人中心：
  - 我的收藏
  - 我的笔记
  - 最近浏览，可选

### 8.3 技术建议

- 先使用 Django 内置用户系统。
- 用户笔记必须和公开内容隔离权限。
- 收藏操作可以使用普通表单提交，不必一开始做 Ajax。

### 8.4 验收标准

- 未登录用户访问收藏功能时跳转登录。
- 登录用户只能查看和编辑自己的笔记。
- 用户能取消收藏。
- 收藏数量在详情页可见，可选。

## 10. 0.9 结构式检索实验版

### 10.1 目标

在已有结构式展示能力基础上，探索子结构检索和结构相似检索。

### 10.2 功能范围

- 管理员录入 SMARTS 官能团模式。
- 用户通过官能团结构检索反应。
- 用户输入 SMILES 检索相关反应或路线。
- 支持子结构匹配。
- 可选支持相似度检索。

### 10.3 技术建议

- 使用 RDKit 做子结构匹配。
- 小数据量阶段可在应用层扫描。
- 数据量增大后再考虑结构指纹缓存或 PostgreSQL 扩展方案。

### 10.4 验收标准

- 用户输入合法 SMILES 后能得到相关反应结果。
- 非法 SMILES 有明确错误提示。
- 官能团检索结果与人工标签结果基本一致。
- 性能在 300 到 500 条反应规模下可接受。

## 12. 数据建设计划

### 12.1 第一批内容

建议先录入 50 个考研高频人名反应，包括：

- Wittig Reaction
- Friedel-Crafts Acylation
- Friedel-Crafts Alkylation
- Aldol Reaction
- Cannizzaro Reaction
- Grignard Reaction
- Diels-Alder Reaction
- Baeyer-Villiger Oxidation
- Claisen Condensation
- Dieckmann Condensation
- Michael Addition
- Hofmann Rearrangement
- Beckmann Rearrangement
- Pinacol Rearrangement
- Gabriel Synthesis

### 12.2 内容模板

每个反应至少包含：

- 中文名
- 英文名
- 别名
- 反应类型
- 标签
- 相关官能团
- 一句话摘要
- 典型 SMILES
- 常用条件
- 机理要点
- 考点
- 易错点
- 参考来源

### 12.3 数据质量检查

每次批量录入后检查：

- 是否有重复 slug。
- 是否有未填参考来源的已发布内容。
- 是否有明显错误 SMILES。
- 是否有路线步骤编号重复。
- 是否有已发布路线但没有步骤。

## 13. 推荐优先级

最推荐的实际推进顺序：

1. 0.2 内容维护增强。
2. 0.3 搜索与分类增强。
3. 数据建设：录入 50 个高频人名反应。
4. 0.4 结构式展示。
5. 数据建设：录入 20 到 30 条合成路线。
6. 0.5 学习专题。
7. 0.8 生产部署。
8. 0.6 数据导入导出。
9. 0.7 用户收藏笔记。
10. 0.9 结构式检索实验版。
11. 1.0 稳定公开版。

这个顺序的理由：

- 项目的核心价值首先来自内容质量。
- 结构式展示很重要，但 RDKit 环境会增加部署复杂度，不适合紧跟 0.1 立刻做大。
- 用户系统在内容不足时价值有限，建议等资料库初步成型后再做。
- 数据导入导出可以在录入压力变大时提前。

## 15. 暂不建议立即开发的功能

- AI 自动生成合成路线。
- 移动 App。
- 复杂用户社区。
- 在线机理动画编辑器。
- 完整前后端分离重构。
- 大规模结构相似搜索。

这些功能可以做，但应等内容库和基础检索稳定后再启动。

---

## 16. 总结

OrganicChemHub 后续更新应走“内容质量优先、检索体验其次、结构能力逐步增强”的路线。0.2 和 0.3 是最关键的过渡版本，它们决定管理员能否高效维护数据、学生能否快速找到内容。

建议短期不要急着做复杂智能功能，而是先把 50 个高频反应和 20 条路线做成稳定、可搜索、可复习的资料库。这样项目会更快形成真实使用价值，也更适合后续同步到 GitHub 持续迭代。
