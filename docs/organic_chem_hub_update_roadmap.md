# OrganicChemHub 后续更新规划

当前版本：**v4.0 评论与公开化（已完成）**
下个版本：**v5.0 待定**
规划日期：2026-08-21（各版本日期见章节标题）

本规划以图片结构式和人工审核内容为核心。后续版本不再规划文本结构式生成、结构编辑器或子结构检索能力，重点回到内容质量、后台效率、考研学习体验和生产运维稳定性。

---

## 1. 更新原则

1. 内容质量优先：先保证反应、路线、图片和考点足够完整。
2. 后台效率优先：管理员可以批量发现问题、批量处理、批量发布。
3. 前台清晰优先：人名反应、常见有机反应、路线和资料入口保持清楚分层。
4. 图片审核优先：结构式通过 SVG/PNG 上传、预览、审核和替换完成。
5. 稳定部署优先：减少复杂运行依赖，服务器更新流程保持简单。

## 3. v2.1 内容发布完善

### 目标

让管理员能清楚知道：哪些内容已经在前台展示，哪些草稿已经补全可以发布，哪些仍然缺关键字段。

### 功能范围

- 首页展示前台内容状态：
  - 已发布人名反应数量。
  - 已发布常见有机反应数量。
  - 已发布合成路线数量。
  - 待发布完整内容数量。
- 内容质量仪表盘新增“可发布草稿”。
- 新增命令 `publish_ready_content`：
  - 只发布完整草稿。
  - 缺方程式图、缺缩略图、缺条件、缺考点或缺参考来源的内容不发布。
  - 支持 `--dry-run` 预览数量。
- 清理旧结构式生成运行依赖，结构式展示继续以后台上传图片为准。

### 验收标准

- 首页能看到“前台内容状态”。
- 仪表盘能看到人名反应和常见有机反应的“可发布草稿”数量。
- 命令能发布完整草稿，并跳过不完整草稿。
- 测试覆盖首页、仪表盘和命令行行为。

## 6. v2.4 内容质量增强

### 目标

让后台从“能管理内容”升级为“能指导补内容”，帮助管理员优先补最影响前台可用性的条目。

### 功能范围

- 内容缺失优先级：
  - 缺方程式图。
  - 缺缩略图。
  - 缺考点。
  - 缺反应条件。
  - 缺参考来源。
- 图片审核状态：
  - 待上传。
  - 待审核。
  - 已通过。
  - 需重画。
- 仪表盘增加补全建议：
  - 本周建议优先补全的 10 条内容。
  - 已发布但质量不足的内容。
  - 草稿中最接近可发布的内容。
- 后台列表增加“下一步动作”列。

### 验收标准

- 管理员不进入详情页也能判断内容缺什么。
- 缺图内容和缺文字内容能分开处理。
- 图片审核状态能筛选、批量更新。

## 7. v2.5 考研专题学习（已完成，2026-08-20）

### 目标

把内容库从“查询工具”提升为“复习工具”，帮助学生按题型和知识块复习。

- 首页新增专题学习和易混反应对比入口。
- 个人中心复习区块：待学习、待复习、已学内容。
- 用户互动模型改为通用内容关联，收藏/笔记/进度支持新老反应库。

### 验收标准

- 前台出现专题入口。
- 每个专题能展示关联内容和复习重点。
- 用户能从专题页进入反应详情和路线详情。

## 8. v2.6 学习进度与复习系统（开发中，2026-08-20）

### 目标

在 v2.5 专题基础上补齐个人学习闭环：专题进度、复习清单和最近学习记录。本版本不新增数据模型，复用现有 `StudyProgress`。

### 实现范围

- 进度服务层 `reactions/services/progress.py`：
  - `topic_progress`：专题已学/总数/待复习/待学习/完成度。
  - `topic_status_map`：反应与路线状态合并映射。
  - `user_topic_summary`：个人中心专题进度聚合。
  - `review_queue` / `recent_activity`：复习清单与最近学习。
- 专题详情"我的专题进度"：进度条 + 已学数/总数 + 完成度 + 三状态统计。
- 专题内反应卡片内联状态切换（复用 `update_progress` 端点）；路线卡片状态徽标。
- 个人中心：专题进度聚合卡片、复习清单（含专题标签）、最近学习时间线。
- 匿名用户不展示任何进度区块。

### 验收标准

- 用户能在一个专题内看到自己的学习进度并直接切换状态。
- 待复习内容有清晰的清单入口。
- 最近学习记录按时间倒序展示。
- 匿名用户不显示任何进度区块与控件。

## 9. v2.7 合成路线扩充（2026-08-20，已完成）

### 目标

让合成路线成为可训练的模块，而不是少量展示页。

### 现状盘点

v2.3-v2.6 迭代中已具备：路线列表搜索、难度筛选、排序（步骤数/难度/最近更新）；详情页步骤时间线（试剂/条件/产率/结构式/说明/关联反应）、优缺点、来源、相关反应、用户互动与访问统计；后台内联步骤编辑与 CSV 导出。本版本在此基础上补齐官能团筛选、关键步骤与维护增强。

### 实现范围（2026-08-20 已完成）

- 模型与迁移 `0021_routestep_is_key_step_and_more`：`RouteStep.is_key_step` 关键步骤标记、`SyntheticRoute.related_functional_groups` 官能团关联（复用现有 `FunctionalGroup`）、`SyntheticRoute.get_key_step_count()`。
- 步骤序号连续性校验：`RouteStep.clean()` 校验序号从 1 开始且连续（无缺号）。
- 后台增强：官能团 `filter_horizontal` 选择与 `list_filter`；列表"关键步骤"数与"缺步骤图"提醒列；内联步骤图片缩略图预览 + `is_key_step` 字段；`RouteStepAdmin` 关键步骤列。
- 前台列表：官能团筛选下拉（`functional_group` 参数按 `name_en` 匹配，与难度/搜索/排序叠加）。
- 前台详情：标题下方官能团徽标（回跳列表预选）、关键步骤时间线金色高亮。
- 不实现：步骤拖拽排序（避免引入第三方 JS）、SMARTS 子结构检索。
- 路线库规模扩充属内容运营：以至少 20 条已发布路线为验收目标，代码层提供完整度与缺图提醒支撑。

### 验收标准

- 用户能按目标官能团找到路线，详情页能聚焦关键步骤。
- 管理员能在路线编辑页维护官能团、关键步骤并预览步骤图片。
- 前台能清楚看到每条路线的学习价值。

## 10. v2.8 运营与审计（2026-08-20，已完成）

### 目标

让网站进入稳定运营状态，减少数据误操作和服务器同步风险。

### 现状盘点

`OpLog` 模型已存在但仅覆盖站内消息群发与清理；批量发布/归档与 CSV 导入无审计；导入错误为纯文本仅页面展示不可下载；部署文档无独立备份恢复章节。

### 实现范围（2026-08-20 已完成）

- 模型与迁移 `0022_contentbatch`：`ContentBatch`（Kind/operator/summary/detail/object_count/created_at）。
- 审计服务层 `reactions/services/audit.py`：`log_operation`（OpLog 统一写入）、`record_batch`（ContentBatch 创建，detail 截断 2000）。
- 批量发布/归档接入：`PublicationActionMixin._publish_selected` / `_archive_selected` 写入 OpLog + ContentBatch。
- CSV 导入接入：`reaction_import_view` 写入 OpLog + ContentBatch；`import_reactions_from_csv` 返回 names 列表。
- 消息工具日志统一：`message_broadcast_view` / `message_cleanup_view` 走 audit 入口。
- 导入错误结构化：errors 改为 dict（line/fields/raw/reason），新增下载端点 `/admin/reactions/import/errors/download/`。
- Admin：`ContentBatchAdmin` 注册（只读），`OpLogAdmin` 已有 action/日期筛选。
- 文档：部署文档新增备份与恢复章节（数据库备份、media 备份、git 回滚、更新检查清单、故障恢复）。

### 验收标准

- 管理员能追踪一次导入或发布影响了哪些内容。
- 导入失败数据能被下载后修复。
- 服务器更新前后有清晰的备份与回滚步骤。

## 12. v4.0 评论与公开化

### 目标

让前台形成基础社区互动，同时让网站可被搜索引擎收录，进入真正可公开访问、可持续积累用户反馈的状态。

### 功能范围

- 评论/社区：
  - 新增 Comment 模型（复用 v2.5 通用内容关联 GFK 模式）：评论者、关联内容、正文、父评论（回复）、隐藏标记、时间戳。
  - 详情页评论区：登录用户可发表评论与回复；匿名用户显示登录引导；评论正序展示、回复缩进。
  - 后台评论管理：按内容/用户/状态筛选，隐藏/恢复与批量操作，隐藏写入 OpLog。
  - 个人中心：我的评论列表（含隐藏状态提示）。
- SEO 公开化：
  - sitemap.xml（django.contrib.sitemaps）：首页、人名反应、常见反应、路线、专题、易混对比、学习资料全部已发布内容。
  - robots.txt：允许收录并指向 sitemap。
  - 详情页 SEO 元信息：独立 title、description、canonical、OG 分享标签。
  - 404/500 错误页：友好提示与返回首页入口。

### 验收标准

- 登录用户能在任何详情页发表和回复评论，管理员能在后台审核隐藏。
- sitemap.xml 覆盖全部已发布内容 URL，robots.txt 正确指向。
- 每个详情页有独立 meta description 与 canonical，分享到社交平台有卡片。
- 错误页友好且可返回首页。

### 明确不做

- 评论点赞/踩、富文本编辑器、表情贴纸；第三方评论系统（Disqus 等）。
- 开放注册策略调整（保持现有注册视图）；评论仅需登录态。
